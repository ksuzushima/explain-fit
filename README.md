# explain fit

説明の「区切り方」を本人内で小さく比較する、日本語の探索用プロトタイプです。能力・学習タイプ・認知特性の診断や、標準化された検査を目的としていません。

## 起動

Node.js 22.12 以上（検証環境：24.19）を使用します。

```sh
npm ci
npm run dev -- --host 127.0.0.1
```

`http://127.0.0.1:5173/` を開きます。ネットワークインターフェースの列挙が制限された実行環境では、上のように明示的にループバックを指定してください。

```sh
npm run typecheck
npm test
npm run build
npm run preview -- --host 127.0.0.1
```

依存関係はReact、React DOMと開発・テスト用ツールのみです。バックエンド、ログイン、LLM、外部フォント、広告・解析SDKはありません。自動公開・デプロイの設定もありません。

## 比較する一軸

- A：同じ説明文を、連続した一つの段落として表示
- B：同じ説明文を、意味のまとまりごとに改行・段落間の余白を付けて表示
- 文言、文の順序、情報量、文字サイズ、行間、説明カードの幅は共通
- 説明本文に箇条書き、要約、図、条件名、優劣を示す文言は追加しない
- 説明は設問表示後も参照可能。測るのは説明を利用した回答であり、短期記憶や純粋な処理速度ではない

元の設計を発展させ、回答中も説明を参照できる仕様にしています。別形式の提示に付随する自然な縦方向の長さの違いはあります。同じ端末、画面サイズ、ブラウザ倍率での実施を推奨します。表示領域は各ラウンド開始時に記録しますが、途中の端末回転や倍率変更の検出は未実装です。

## 実施の流れ

1. 保存先・所要時間・限界を確認し、類似のルール問題への慣れを回答
2. 2課題で練習（練習を済ませている場合はスキップ可能）
3. 初回の未見8課題：読む → 問題に進む → 4問に回答 → 努力と好みの評定
4. 4課題のあと、任意の休憩
5. 正答、時間、精神的な努力、好みを独立して確認
6. 別の暦日に、未見の再確認8課題（同じローカル端末の記録が必要）
7. 再確認完了後に、本番の正解と解説を表示

8課題・15〜20分は試作の設計目安であり、実施時間・適切な必要量・判断精度は未検証です。

### 課題と割当

`src/tasks.ts` に18課題・72設問を収録しています。

- 練習2課題
- 初回4ペア8課題
- 再確認4ペア8課題。初回と文章を共有しない
- ペアの推論構造：独立加算、上限、優先する例外、複数条件
- 各課題：内容確認1問と応用3問。すべて選択式・固定正解で機械的に採点
- 本番本文は210〜245文字、各ペアの文字数差は最大11文字。これは難度同等性を保証しない

ラウンドごとに `ABBA BAAB` または反転した `BAAB ABBA` を乱数で選びます。ペアの順序と、ペア内の内容割当もランダム化します。どのペアも片方A・もう片方Bとなり、前半・後半で各条件2課題ずつ、全体4課題ずつです。seed、全割当、順番、教材版を記録し再現可能にしています。同じ参加記録で同じセットを再利用できません。

### 計測と欠測

- 最初に読む時間：説明を開いてから「問題に進む」まで
- 解く時間：設問を表示してから回答を確定するまで。説明の読み直しを含む
- 合計時間：上記2区間の和。評定・休憩は含めない
- 手動一時停止、タブを離れる、ホームへ戻る操作は計時を止める
- 再読み込み後は一時停止。離脱中の時間は加算せず、進行中だった課題の時間を不確実と記録
- 時間の条件別平均には、全問回答済み・スキップなし・中断なし・時間不確実性なしの完了課題のみを使用。集計対象数を表示
- 評定画面での中断も保守的に時間集計から除外する
- 未回答・未着手は誤答とは別の欠測として保持。正答 / 回答済みの分母と未回答・未確定数を明記。評定前でも確定済みの回答は採点に含め、回答中の未確定入力は含めない
- スキップ、部分完了、全問正解（天井の可能性）、全問不正解（床の可能性）を表示

時間はブラウザの時計で測る探索的値です。システム時計の前方変更、バックグラウンド通知の遅延などの影響は完全には排除できません。

### 評定と結果

1〜7の精神的な努力項目は、この試作独自の探索用質問です。Paas（1992）の9件法を、妥当性が確認された形で実装したものではありません。「次もこの表示を使いたい」の1〜7評定と、ラウンド末のA/B/同程度/わからないという好みも、正答と独立させています。

結果は条件別の実測記述とペア別応用成績です。総合点、優劣の自動判定、IQ、診断名、パーセンタイル、最適である確率、固定的なタイプは表示しません。各形式4課題という少数比較で「差なし」は同等の証明ではありません。短い時間・小さい努力だけを良い理解と解釈できず、正答や欠測の条件が異なる時間比較には特に注意が必要です。

別日の方向一致も、画面の各回記録から確認する探索的材料です。統計検定、信頼区間、差の自動認定は行いません。一般課題からコード理解やClaude Codeの実作業への転用は別に確かめてください。

## データの扱い

保存先は同一オリジン・同一ブラウザのlocalStorage（キー `explain-fit:v1`）です。外部に回答を送信しません。保存期限は自動設定せず、アプリ内の確認付き削除かブラウザのサイトデータ削除まで残ります。シークレットモードやサイトデータ消去により失われる場合があります。別端末との同期はありません。

保存対象は課題ID・版、日付、割当、seed、画面サイズ、言語、類似問題への慣れ、回答、時間、評定、中断と進行状況です。名前、連絡先、診断・健康情報は不要で、収集しません。練習回答は記録に残しません。複数タブで同時に実施しないでください。他のタブから更新・削除を検知すると、古い画面からの自動保存を止め、再読み込みを案内します。公開サーバーに配置する場合、通常の配信アクセスログがサーバー側に残る可能性は別途あります。

JSON書き出しには、生データ、採点結果、集計、欠測方針、全教材と正解を含めます。別日再確認の前に正解を読むと、未見性が失われます。JSONを第三者へ共有する場合は利用者が内容・日時を確認してください。取り込み機能は未実装です。不正・未対応の保存データは自動上書きせず、画面に警告します。

## 根拠と外挿の限界

以下は設計上の慎重さを支える資料です。この8課題セット、静的日本語文章の改行効果、個人への効果を検証した研究ではありません。

1. **Pashler et al., Learning Styles: Concepts and Evidence**。好みの存在と、好みに合わせることで成績が上がるという主張を区別する。固定学習者タイプを割り当てない理由。[論文PDF](https://bjorklab.psych.ucla.edu/wp-content/uploads/sites/13/2016/07/Pashler_McDaniel_Rohrer_Bjork_2009_PSPI.pdf)
2. **Rey et al. (2019), segmentation meta-analysis**。マルチメディア分割研究で成績・負荷と学習時間を分ける理由になる。静的日本語文の改行への直接的証拠ではない。[DOI](https://doi.org/10.1007/s10648-018-9456-4)
3. **Paas (1992)**。成績に加えて精神的努力を扱う一次研究。本試作の独自1〜7質問を妥当化するものではない。[DOI](https://doi.org/10.1037/0022-0663.84.4.429)
4. **Deslauriers et al. (2019)**。学べた感覚と実際の成績が一致しない場合がある。主観を理解の代用にしない根拠。[DOI](https://doi.org/10.1073/pnas.1821936116)
5. **Kalyuga, Chandler & Sweller (1998)**。熟練度によって説明の有利さが変化し得る。設定候補に用途と確認条件を残す理由。[DOI](https://doi.org/10.1518/001872098779480587)
6. **Cariveau et al. (2022)**。異なる教材を交互比較する方法と、その教材差・持越し効果の限界。本試作の必要試行数や判断精度を保証しない。[DOI](https://doi.org/10.1002/bin.1865)

説明設定へ反映するときは「本人の好み」「一般課題での暫定観測」「実作業で再確認済み」を混同せず、用途と確認日を付けて見直せる仮説にします。

## 実装と検証

- `src/tasks.ts`：課題文、設問、固定採点基準
- `src/engine.ts`：割当、状態遷移、計時、保存検証、集計、JSON
- `src/engine.test.ts`：46テスト（seed 1,000種類×2セットの割当を含む）
- `src/App.tsx`：日本語の操作画面と各段階
- `src/styles.css`：レスポンシブ表示。A/Bは共通の本文CSSを使用

テストは内容の不変性、未見性、均衡割当、採点、未回答、中断・復帰、再読み込み、不正保存データ、床・天井・未完了、JSON書き出しを確認します。課題の正答キーは別途72問を算術・論理で照合しました。

未実施の研究：利用者による予備試行、項目難度・並行性の検証、所要時間の実測校正、再検査信頼性、改行効果の因果推定、実務への転移。これらの検証前に人の能力や特性を判断する目的で使わないでください。
